Документация программы screen.pyw (UDP_ABG, версия 2.0.0)

1. Назначение программы

screen.pyw — настольное приложение на Python/Tkinter для трансляции экрана (или его части) по локальной сети через UDP broadcast, без сервера и без необходимости знать IP получателей заранее. Программа объединяет четыре функции в одном GUI:

  1. Трансляция экрана — захват выбранной области экрана и рассылка её всем компьютерам в локальной сети.

  2. Приём трансляции — просмотр чужой трансляции в отдельном окне.

  3. Передача файлов — рассылка произвольного файла по сети (UDP broadcast, с проверкой целостности по MD5).

  4. Приём и выполнение команд — приём текстовых команд от других участников сети и их выполнение (как встроенных, управляющих самим приложением, так и произвольных команд ОС).

Каждый экземпляр программы может быть одновременно и передатчиком, и приёмником — роль определяется тем, какие действия выполняет пользователь, а не отдельным режимом запуска.

⚠️ Важное предупреждение. Раздел 4 (приём и выполнение команд) в текущей реализации не имеет аутентификации: любой узел в той же broadcast-сети может отправить программе команду ОС на выполнение (subprocess.run(..., shell=True)), включая встроенную команду выключения компьютера. Это существенный риск безопасности — подробнее в разделе 8 «Предложения по улучшению».

3. Алгоритм работы
3.1 Запуск программы

  1. Проверка, не запущена ли уже программа (бинд на 127.0.0.1:5009; если порт занят — выход).

  2. Создание папки files рядом со скриптом (если её нет).

  3. Определение локального IP: поиск реального Ethernet/Wi-Fi адаптера через psutil, исключая VPN и виртуальные сети; если psutil недоступен или подходящих адаптеров не нашлось — запасной способ через "фиктивный" connect() UDP-сокета.

  4. Создание главного окна, построение интерфейса, заполнение списка сетевых адаптеров.

  5. Автоматический запуск фоновых потоков приёма файлов (порт 5007) и приёма команд (порт 5008) — они слушают сеть постоянно, независимо от того, идёт трансляция экрана или нет.

  6. Регистрация горячих клавиш.

  7. Окно сворачивается в панель задач сразу после запуска (self.root.state('iconic')).

3.2 Трансляция экрана (поток broadcast_screen)

Цикл работает в отдельном потоке, пока флаг self.broadcasting == True:

  1. Захват скриншота выбранной области (ImageGrab.grab).

  2. Раз в секунду (или если это первый кадр) отправляется keyframe — полный кадр в JPEG (качество 75).

  3. Между keyframe-ами вычисляется прямоугольник изменившейся области (_diff_bbox): текущий и предыдущий кадр уменьшаются в 4 раза, сравниваются через ImageChops.difference, находится bounding box изменившихся пикселей, который затем масштабируется обратно с запасом.

    • Если изменений нет — кадр вообще не отправляется (экономия трафика).

    • Если изменившаяся область больше 50% площади экрана — отправляется keyframe вместо delta (лучше сжимается, проще для приёмника).

    • Иначе отправляется delta-кадр: только изменившийся прямоугольник, кодированный в JPEG (качество 80), с координатами (x, y, w, h).

  4. Кадр (keyframe или delta) нарезается на чанки по 1400 байт (укладываются в Ethernet MTU без IP-фрагментации) и рассылается через sock.sendto() на 255.255.255.255:5006. Каждый чанк снабжён 16-байтным заголовком (frame_id, chunk_idx, total_chunks, chunk_len).

  5. Скорость цикла подстраивается под целевой FPS (15 кадров/с) с учётом реально потраченного на захват/сравнение/кодирование времени.

Формат payload кадра (после сборки из чанков, до разбора):

[1 байт: тип кадра]
  0 = keyframe: далее -- сразу JPEG-байты всего кадра
  1 = delta:    далее -- 8 байт (x:H, y:H, w:H, h:H) + JPEG-байты области
3.3 Приём трансляции (поток receive_screen)

  1. Сокет привязывается (bind) к IP выбранного сетевого адаптера и порту 5006 — пакеты с других интерфейсов (VPN, виртуальные сети) физически не попадают в этот сокет.

  2. При получении пакета сначала проверяется IP отправителя: если это тот же адаптер, с которого программа сама транслирует — пакет игнорируется (иначе передатчик видел бы собственную трансляцию, т.к. broadcast возвращается и отправителю).

  3. Чанки складываются в буфер по frame_id, пока не соберутся все total_chunks.

  4. Собранный payload разбирается: если keyframe — заменяет весь «холст» (self.canvas_image); если delta — вставляется (paste) в холст по координатам.

  5. Холст конвертируется в PhotoImage и отображается в окне приёма.

  6. Незавершённые (частично собранные) кадры чистятся по количеству (не больше 10 в буфере) и по возрасту (старше 1 секунды — значит, чанк потерян и кадр никогда не соберётся).

3.4 Передача и приём файлов

  • Отправка (_send_file_thread): файл читается целиком, считается MD5, рассылается служебный пакет FILE_START (метаданные: имя, размер, хеш, число чанков — отправляется 3 раза подряд для надёжности), затем данные нарезаются на чанки по 60000 байт и рассылаются как FILE_CHUNK, в конце — FILE_END.

  • Приём (_receive_files_thread, фоновый, запущен постоянно): собирает чанки по индексам, при получении всех — склеивает файл, сверяет MD5; при совпадении сохраняет в папку files (при конфликте имён добавляется числовой суффикс), при несовпадении — сообщает об ошибке контрольной суммы.

3.5 Передача и приём команд

  • Отправка (_send_command_thread): текст команды кодируется в UTF-8, упаковывается в пакет COMMAND_EXEC + длина + текст, отправляется один раз на порт 5008.

  • Приём (_receive_commands_thread, фоновый, запущен постоянно): при получении пакета проверяется IP отправителя (свои же команды игнорируются), команда передаётся в _execute_command в отдельном потоке.

  • Выполнение (_execute_command): сначала проверяется, не совпадает ли первое слово команды с одной из встроенных (set_size, start_view, stop_view, stop_trans, clear_files) — если да, вызывается соответствующий метод приложения. Если нет — команда целиком передаётся в subprocess.run(command, shell=True, timeout=30), то есть выполняется как обычная команда операционной системы без какой-либо проверки прав или источника.

3.6 Горячие клавиши и режимы

Горячие клавиши регистрируются глобально (bind_all) и работают независимо от фокуса окна:

КлавишаДействие
Ctrl+TВключить режим передатчика (показать все панели передачи)
Ctrl+RВыключить режим передатчика (оставить только приём)
Ctrl+UБыстрый режим (только кнопки быстрого выбора области)
Ctrl+FВыбрать и отправить файл
Ctrl+IПоказать свой IP-адрес
Ctrl+HПоказать окно справки
Ctrl+ZПолностью завершить программу
Ctrl+-Очистить папку files локально и разослать команду очистки всем ПК сети
Ctrl+NОткрыть системную оснастку сетевых подключений (ncpa.cpl)
Ctrl+XРазослать команду выключения всем ПК сети (с подтверждением через диалог)

Закрытие окна крестиком не завершает программу — она сворачивается в фоновый режим (продолжает слушать порты файлов/команд), поскольку on_close вызывает self.root.iconify(), а не destroy().

6. Способы использования программы
6.1 Запуск

Программа запускается двойным щелчком по screen.pyw (расширение .pyw — без консольного окна) или командой:

pythonw screen.pyw

Требуется установленный Python 3, Pillow (pip install Pillow) и желательно psutil (pip install psutil) для корректного выбора сетевого адаптера. После запуска окно сразу сворачивается в панель задач — программа работает в фоне, слушая приём файлов и команд.

6.2 Как транслировать экран

  1. Развернуть окно из панели задач, включить режим передатчика — Ctrl+T (или воспользоваться «Быстрым режимом» — Ctrl+U).

  2. Выбрать сетевой адаптер в блоке «Сетевой адаптер», если авто-выбор не устраивает.

  3. Выбрать область: кнопкой «Выбрать область» (произвольный прямоугольник мышью) либо одной из кнопок быстрого выбора («Показать весь экран» / «левую половину» / «правую половину» — они же сразу запускают трансляцию и рассылают команду приёмникам подключиться).

  4. Нажать «Начать трансляцию» (если область выбиралась вручную).

  5. Для остановки — «Остановить трансляцию» или «Завершить показ экрана» (останавливает и рассылает команду отключения приёмникам).

6.3 Как смотреть чужую трансляцию

  1. Переключиться в режим приёмника — Ctrl+R (или это режим по умолчанию при запуске).

  2. Нажать «Подключиться к трансляции» — откроется окно, в котором появится изображение, как только по сети пойдут пакеты с транслируемым экраном.

  3. «Отключиться от трансляции» или закрытие окна приёма (крестик/Escape) останавливает приём.

6.4 Как передать файл

  1. Ctrl+F или кнопка «Выбрать и отправить файл» — открывается диалог выбора файла (по умолчанию — папка files).

  2. Файл рассылается всем компьютерам сети; принятые файлы автоматически появляются в их папках files.

6.5 Управление удалённо через команды

Кнопки R/F/S/X в блоке «Передача файлов» рассылают предопределённые команды всем компьютерам сети одновременно:

  • R — запустить просмотр трансляции на всех приёмниках.

  • F — задать окну приёма размер, равный размеру транслируемой области.

  • S — остановить просмотр на всех.

  • X — прекратить трансляции на всех.

Кнопка «Отправить команду» позволяет ввести произвольную команду ОС, которая будет выполнена на всех компьютерах, где запущена программа и слушает приём команд.

6.6 Типичный сценарий (демонстрация с экрана учителя/докладчика)

  1. Докладчик: Ctrl+U → «Показать весь экран» — единственное действие, которое запускает трансляцию и автоматически рассылает команды на подключение и подгонку размера всем слушателям.

  2. Слушатели: программа уже в фоне, окно приёма откроется автоматически по команде start_view/full_size.

  3. По завершении — «Завершить показ экрана» у докладчика останавливает всё и у него, и у слушателей.

7.2 Статусные метки в интерфейсе

Помимо консоли, программа активно использует два текстовых Label-виджета как индикаторы состояния «что сейчас происходит»:

  • self.status (верхняя метка окна) — состояние трансляции/приёма/адаптера: выбор области, старт/остановка трансляции, ошибки привязки сокета, смена адаптера, подключение/отключение приёма.

  • self.file_status (в блоке «Передача файлов») — прогресс отправки/приёма файлов (в процентах), результат отправки команд, ошибки контрольной суммы.

Цвет текста меток служит быстрым визуальным индикатором: green/blue — успех/процесс, gray — нейтрально/ожидание, red — ошибка, orange — предупреждение (например, «адаптер изменён, нужен перезапуск трансляции»).

7.3 Рекомендация по улучшению отладки

Текущая схема (print + цветные метки) неудобна для диагностики постфактум — вывод print() не сохраняется, если программа запущена как .pyw (без консоли). Рекомендуется заменить на модуль logging с записью в файл рядом со скриптом (screen.log) и уровнями DEBUG/INFO/WARNING/ERROR — подробнее в разделе 8.

8. Предложения по улучшению программы
8.1 Критично — безопасность

  1. Отсутствие аутентификации приёма команд. _execute_command выполняет через subprocess.run(command, shell=True) любую команду, пришедшую по UDP на порт 5008, без проверки источника или прав доступа. Любой узел в той же broadcast-сети может получить выполнение произвольного кода на машине, где запущена программа. Рекомендация: добавить общий секретный ключ/токен (HMAC-подпись пакета), либо белый список разрешённых команд, либо явное подтверждение пользователем перед выполнением непредопределённых команд.

  2. Команда shutdown /p, рассылаемая по Ctrl+X, необратима и, при отсутствии аутентификации из п. 1, теоретически может быть инициирована с любого узла сети, а не только через горячую клавишу этой программы (учитывая, что протокол COMMAND_EXEC не проверяется). Минимум — привязать подобные деструктивные команды к дополнительному подтверждению на стороне получателя, а не только у отправителя.

  3. clear_files по сети без подтверждения — аналогичная логика: любой узел в сети может стереть содержимое папки files на всех остальных.

  4. _send_file_thread/_receive_files_thread без проверки размера/типа файла. Вредоносный или ошибочный отправитель может заполнить диск получателя произвольным файлом без ограничения размера.

8.2 Дублирование кода / логические баги

  1. Дублирование методов run и on_close. Оба метода определены дважды в классе ScreenBroadcaster (первая версия — мёртвый код, перекрывается второй). Стоит удалить первые версии, чтобы не вводить в заблуждение при чтении/доработке кода.

  2. show_ip показывает my_ipaddr (глобальную переменную, определённую один раз при старте), а не self.local_ip (который пользователь мог изменить в интерфейсе после запуска). Стоит унифицировать источник — использовать self.local_ip везде, а my_ipaddr оставить только как значение по умолчанию при инициализации.

8.3 Сеть и производительность (частично уже реализовано в ходе прошлых доработок)

  1. Уже сделано: MTU-safe чанки (1400 байт), keyframe/delta-кодирование, адаптивный FPS, фильтрация по адаптеру, самофильтрация broadcast-петли.

  2. Дальнейшее ускорение захвата экрана — заменить PIL.ImageGrab на mss (значительно быстрее на Windows за счёт DXGI/BitBlt), особенно для больших областей и высокого целевого FPS.

  3. Более точная сегментация delta-кадров. Сейчас delta — единственный bounding box изменений; при нескольких разнесённых по экрану изменившихся зонах (например, курсор в одном углу и обновление часов в другом) box может охватывать почти весь экран впустую. Разбиение на независимые прямоугольники (dirty rectangles) или тайловая сетка с отдельной отправкой только изменившихся тайлов дало бы дополнительную экономию.

  4. Multicast вместо broadcast — при известном/ограниченном числе получателей переход на IP-multicast с IGMP снизил бы нагрузку на сетевое оборудование по сравнению с 255.255.255.255, которая обрабатывается всеми узлами сегмента независимо от того, интересуются ли они трансляцией.

  5. Восстановление после потери UDP-пакетов файлов и команд — сейчас _send_file_thread не имеет подтверждений/повторных передач по чанкам (только FILE_START/FILE_END дублируются 3 раза), и большие файлы на нестабильной сети могут не собраться на приёмнике вообще без явного сообщения об этом отправителю.

8.4 Код и поддерживаемость

  1. Замена print() на модуль logging с записью в файл рядом со скриптом и уровнями важности — критично, так как .pyw-запуск скрывает консоль и вся текущая диагностика через print() просто теряется.

  2. Вынесение сетевых констант (порты, broadcast_ip, размеры чанков, целевой FPS, качество JPEG) в конфигурационный файл (config.ini/config.json) вместо жёстко заданных значений в коде — упростит настройку под разные сети без правки исходников.

  3. Обработка исключений слишком широкая в ряде мест (except Exception as e: print(...)) — усложняет диагностику специфичных проблем (например, разрыв сети vs. повреждённые данные vs. ошибка декодирования JPEG). Стоит разделять типы исключений там, где это осмысленно.

  4. Отсутствие docstring-описаний у части методов (_diff_bbox, _send_frame_payload, broadcast_screen, receive_screen и др. частично документированы только инлайн-комментариями) — для дальнейшей поддержки кода стоит унифицировать документирование через docstring, как это уже сделано для части встроенных команд (set_size, start_view и т.д.).

  5. UI собран императивно в одном длинном init — вынесение построения каждой панели в отдельные приватные методы (_build_broadcast_panel, _build_receive_panel и т.д.) упростило бы чтение и модификацию интерфейса.
